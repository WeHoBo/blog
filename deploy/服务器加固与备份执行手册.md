## 2. ⚠️ 上线前必查：`jwt.secret` 长度

新的 `JwtUtils` 会在启动时校验密钥 **≥ 32 字节**。**现有密钥若太短，后端会直接起不来**（这是有意的 fail-fast）。
先量一下：

```bash
# 情况 A：配置里写的是明文
sudo grep -A5 '^jwt:' /opt/blog/application-prod.yml | grep 'secret:'

# 情况 B：配置里写的是 ${JWT_SECRET:}（迁移后就是这样）
sudo grep '^JWT_SECRET=' /opt/blog/blog.env | awk -F= '{print "当前 JWT_SECRET 长度: " length($2)}'
```

- 长度 **≥ 32** → 跳过本步。
- 长度 **< 32 或没有** → 生成一个并写入 `blog.env`：

```bash
NEW_SECRET=$(openssl rand -base64 48)
sudo grep -q '^JWT_SECRET=' /opt/blog/blog.env \
  && sudo sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$NEW_SECRET|" /opt/blog/blog.env \
  || echo "JWT_SECRET=$NEW_SECRET" | sudo tee -a /opt/blog/blog.env
```

⚠️ **换密钥 = 所有人当前登录态立即失效、必须重新登录**（包括你自己）。若暂时不想掉线，先跳过本步，
但务必保证现有密钥长度 ≥ 32。

## 4. ⚠️ 给 Redis 加密码

> 顺序很重要：**先改 Redis 并重启 → 再写 blog.env → 最后重启后端**。
> 中间后端会连不上 Redis，登录/缓存会短暂不可用，挑低峰做。

```bash
# 4.1 生成强密码
REDIS_PW=$(openssl rand -base64 24)
echo "生成的 Redis 密码（记下来）：$REDIS_PW"
```

```bash
# 4.2 写入 redis.conf（先用 `ps -ef | grep redis` 确认配置路径，常见 /etc/redis/redis.conf）
REDIS_CONF=/etc/redis/redis.conf

if grep -qE '^[[:space:]]*requirepass ' "$REDIS_CONF"; then
  sudo sed -i "s|^[[:space:]]*requirepass .*|requirepass $REDIS_PW|" "$REDIS_CONF"
else
  echo "requirepass $REDIS_PW" | sudo tee -a "$REDIS_CONF" >/dev/null
fi
sudo grep -n '^requirepass' "$REDIS_CONF"

# 4.3 重启 Redis（服务名可能是 redis / redis-server）
sudo systemctl restart redis    # 失败就试：sudo systemctl restart redis-server

# 4.4 验证密码生效（返回 PONG 即成功；提示 NOAUTH 说明没生效）
redis-cli -a "$REDIS_PW" ping
```

```bash
# 4.5 写入 blog.env 供后端读取
sudo grep -q '^REDIS_PASSWORD=' /opt/blog/blog.env \
  && sudo sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=$REDIS_PW|" /opt/blog/blog.env \
  || echo "REDIS_PASSWORD=$REDIS_PW" | sudo tee -a /opt/blog/blog.env

# 4.6 收紧敏感文件权限
sudo chmod 600 /opt/blog/blog.env /opt/blog/application-prod.yml
sudo chown ecs-user:ecs-user /opt/blog/blog.env /opt/blog/application-prod.yml
```

## 5. RAG 调用令牌（两侧必须一致）

先找到 RAG 的真实部署位置与数据目录：

```bash
# RAG 进程怎么起的
ps -ef | grep -iE "uvicorn|main.py|rag" | grep -v grep
# 向量数据在哪
sudo find /opt -maxdepth 5 -type d -name chroma 2>/dev/null
```

设置令牌（**同一个值写进两侧**）：

```bash
TOKEN=$(openssl rand -hex 32)

# Java 侧
sudo grep -q '^RAG_API_TOKEN=' /opt/blog/blog.env \
  && sudo sed -i "s|^RAG_API_TOKEN=.*|RAG_API_TOKEN=$TOKEN|" /opt/blog/blog.env \
  || echo "RAG_API_TOKEN=$TOKEN" | sudo tee -a /opt/blog/blog.env

# RAG 侧（把路径换成上面查到的真实 .env 路径）
RAG_ENV=/opt/blog/rag/backend/.env
sudo grep -q '^RAG_API_TOKEN=' "$RAG_ENV" \
  && sudo sed -i "s|^RAG_API_TOKEN=.*|RAG_API_TOKEN=$TOKEN|" "$RAG_ENV" \
  || echo "RAG_API_TOKEN=$TOKEN" | sudo tee -a "$RAG_ENV"
```

```bash
# 重启 RAG（按你的实际启动方式）
sudo systemctl restart blog-rag        # 或 nohup/supervisor 等

# 验证：不带令牌应当被拒（预期 401/403），带令牌才通
curl -s -o /dev/null -w "无令牌: %{http_code}\n" http://127.0.0.1:8000/
```

## 7. 每日备份 + 定时任务

```bash
# 7.1 部署脚本与配置
sudo cp deploy/backup.sh          /opt/blog/backup.sh
sudo cp deploy/backup.env.example /opt/blog/backup.env
sudo chmod 700 /opt/blog/backup.sh
sudo chmod 600 /opt/blog/backup.env

# 7.2 填配置（DB 密码、RAG 数据路径）
sudo vi /opt/blog/backup.env
#   DB_NAME=blog
#   DB_USER=root
#   DB_PASSWORD=<你的库密码>
#   BACKUP_ROOT=/opt/blog/backups
#   KEEP_DAYS=7
#   RAG_DATA_DIR=<第 5 步查到的 data 目录>
```

```bash
# 7.3 先手动跑一次，确认产出正常
sudo mkdir -p /opt/blog/backups
sudo bash -c 'set -a; . /opt/blog/backup.env; set +a; /opt/blog/backup.sh'
ls -lhR /opt/blog/backups/ | head -30
```

期望看到当天目录里有：`db-blog.sql.gz`、`uploads.tar.gz`（若图片都在 OSS 则可能跳过）、
`rag-data.tar.gz`、`MANIFEST.txt`。

```bash
# 7.4 加 cron（root 身份，每天 03:17，错开整点）
sudo crontab -e
```

加入这一行：

```cron
17 3 * * * bash -c 'set -a; . /opt/blog/backup.env; set +a; /opt/blog/backup.sh' >> /opt/blog/backups/backup.log 2>&1
```

```bash
# 7.5 确认已写入
sudo crontab -l
```

**建议做一次恢复演练**（用临时库，别碰生产库）：

```bash
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS blog_restore_test"
gunzip -c /opt/blog/backups/<时间戳>/db-blog.sql.gz | mysql -u root -p blog_restore_test
mysql -u root -p -e "SELECT COUNT(*) FROM blog_restore_test.article"
mysql -u root -p -e "DROP DATABASE blog_restore_test"
```
