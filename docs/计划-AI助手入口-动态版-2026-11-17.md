## 一、先说结论

你的方案**骨架是对的**，不需要推翻：分层加载（先判断再加载）、静默降级、配置化、不阻塞首屏——这四条我全部保留。

问题在于它是**「静态入口」**：整个生命周期只有三步——放一张占位图 → 换成 Live2D → 待机等点击。模型只在「被点」那一刻有反应，其余时间它和一张会眨眼的图片没区别。

**「动态」的本质不是「会动的图」，是「入口会讲状态」**：AI 在思考、在查资料、在打字、答不上来，入口的样子就该变。你这套面板里**已经有这些状态**（`streaming` / `phase` / `steps`），现在它们只体现在聊天窗口里，血完全没流到入口上。

所以我改的核心只有一句：**把入口做成一个状态机的渲染器**，桌面上用 Live2D 画，手机上用 CSS 画（同一个状态机，两套画笔）。

## 二、「动态」有三种理解，请确认你要哪一种

| | 含义 | 效果 | 我的判断 |
|---|---|---|---|
| **D1 状态动态**（我推荐） | 入口随 AI 状态变形：待机呼吸 → 思考眯眼 → 查资料抬头 → 回答时嘴巴跟着字动 → 答错垂头 → 长时间无交互打盹 | 用户能"看"到它在干活，不用盯着面板 | ✅ 主方案 |
| **D2 交互动态** | 视线跟随鼠标、点击触发动作、拖动换位置、滚动时轻微视差 | 更像桌宠，趣味强 | ✅ 作为 D1 的附加层（桌面端） |
| **D3 形态动态** | 入口随页面/滚动变形（首页是大鱼，文章页缩成小图标） | 视觉噱头 | ⚠️ 建议先不做，容易变成"到处乱跳" |

**我的建议是 D1 + D2，D3 留到以后**。如果你的意思其实是 D3，告诉我，方案要重写。

## 四、方案对比

| | A：纯 Live2D（你的原方案） | B：纯 CSS/SVG 小鱼（不用 Live2D） | **C：状态机 + 双渲染器（推荐）** |
|---|---|---|---|
| 桌面效果 | 生动 | 干净但简单 | 生动 |
| 手机 | 静态图（你原方案） | 动 | **动（CSS 渲染器）** |
| 流量 | 首次 5MB+ | ~8KB | 桌面 5MB / 手机 8KB |
| 视觉风险 | 高（彩色角色 vs 克制调性） | 低（自己画，能配色） | 可控（桌面限一处） |
| 工作量 | 中 | 低 | 中偏高（1.5 倍） |
| 失败时 | 退回静态图（不动） | 无失败面 | 退回 CSS 渲染器（**仍然在动**） |

**推荐 C**：桌面用 Live2D 承担"好玩"，手机和失败态用 CSS 小鱼承担"仍然在动"。同一个 `state`，两套画笔。

## 五、推荐方案（C）详解

### 5.1 架构

```
AiFloat（现有面板，不改聊天逻辑）
   │ 写入状态
   ▼
composables/useCompanionState.ts   ← 唯一状态源（9 个状态）
   │ 读取状态
   ├─► components/companion/CompanionLive2D.vue   桌面：模型 + 气泡
   └─► components/companion/CompanionCSS.vue      手机/降级：SVG 小鱼 + 动效
        ↑
   AI 入口按钮位（原 AiFloat 的 56px 按钮位置，由上面两者之一接管）
```

要点：**状态只有一个源**，两套渲染器都是消费者。任何一套坏掉，换另一套即可，聊天功能不受影响。

### 5.2 状态机（9 态）

| 状态 | 触发源（现有代码里都有） | Live2D 表现 | CSS 小鱼表现 |
|---|---|---|---|
| `idle` | 默认 | 呼吸 + 随机眨眼 + 视线跟随 | 轻微浮动 + 眨眼 |
| `hint` | 首次访问（`localStorage` 一天一次） | 招手一次 + 气泡「点我聊聊」 | 气泡 + 尾巴摆快 |
| `thinking` | `streaming && !msg.content` | `showThinking('正在想…')` + 眯眼 | 头顶三点跳动 |
| `tools` | `msg.steps` 里 `state==='start'` | `showToolCall(工具名, 'loading')` → `'success'` | 转小圆圈 + 文案 |
| `typing` | `streaming && msg.content 在增长` | 口型跟着字动（POC 后再定） | 嘴巴开合 |
| `done` | 流结束 | 点头/眨眼一次 → 1.5s 回 idle | 吐个泡泡 → idle |
| `error` | catch / `code!==200` | 气泡「暂时答不上来」→ 3s 回 idle | 头顶冒「?」 |
| `sleep` | 90s 无交互 | `widget.sleep()`，点击唤醒 | 闭眼 + 冒 Z |
| `hidden` | `visibilitychange` | 暂停渲染循环 | 暂停动画 |

面板打开时额外一个 `panelOpen`：模型**缩小并移到左下角**（或 `sleep()`），避免和 `bottom-4 right-4` 的面板打架。

### 5.3 加载策略（你原方案保留，改成 Nuxt 版）

你写的四条前置判断（宽度 ≥1024 / saveData / effectiveType / WebGL）**全部保留**，但执行位置必须改：

```ts
// 只在客户端、只在 onMounted 之后
onMounted(async () => {
  if (!shouldLoadLive2D()) return useCssRenderer()   // 降级不是"不显示"，是换画笔
  requestIdleCallback?.(boot, { timeout: 3000 }) ?? setTimeout(boot, 2000)
})
```

必须遵守的三条（这个项目踩过的坑）：
1. **不能出现在 `setup()` 里**——`window` 在 SSR 不存在，会 500。
2. **不能写进 `<head>` 同步脚本**——会阻塞首屏，也会和水合打架。
3. **模型容器用 `ClientOnly` 包裹**——否则服务端吐空 div、客户端吐 canvas，水合报错。

### 5.4 入口融合（关键取舍）

记忆里有一条硬约束：**入口不许重复**。所以不能「大肥鱼飘着 + 旁边还有个圆按钮」。做法：

- 桌面（≥1024 且通过前置判断）：模型**就是**按钮，点击开面板；
- 其它情况：CSS 小鱼**就是**按钮，点击开面板；
- `AiFloat.vue` 里那个 `<button>` 改成 `<CompanionEntry @click="toggle" />`，聊天面板一行不动。

### 5.5 模型资源（这条你得先解决）

- 你给的 `ygc06/fishpet-release`、`lcyyun/deepseek-chan-companion` 我都查了，**仓库存在**（各 2 star，2026-11 还有提交），但**都没有 LICENSE 文件**。没有许可证 ≠ 授权，个人非商业站点自用一般没问题，但：
  - 放 `public/models/` 等于**公开可下载**，属于「再分发」，性质和"自己用"不同；
  - 代码注释里保留来源（你方案第九条已经写了，这点很好）。
- 更稳的做法：模型**不进 git**（加 `.gitignore`），部署包单独放，服务器上手工解压到 `/opt/blog/web/.output/public/models/`。这样仓库不变大、也不再分发。
- 前置条件：必须拿到含 `*.model3.json / *.moc3 / 贴图.png / physics3.json / motion3.json` 的**完整目录**，且 json 内是相对路径。拿不到 → 直接走 CSS 渲染器，方案不卡住。

### 5.6 视觉（我唯一强建议改的地方）

全站是暖纸 + 墨色 + 单一陶土色、低饱和低明度。一只高饱和的彩色角色会成为页面上**唯一的刺眼点**。三条收敛手段，任选或叠加：

1. 容器加 `filter: saturate(.82) brightness(.98)`（不动贴图，随时可调回）；
2. 尺寸压到 **150×190** 以内（你方案写的 180×220 偏大，右下角会压到"回到顶部"之类）；
3. 暗色模式下加一层 `mix-blend-mode` 或半透明纸感底，避免白底突兀。

### 5.7 失败与降级矩阵

| 失败点 | 现在的行为（你方案） | 改成 |
|---|---|---|
| 模型 404 / 解析失败 | 静态 WebP（不动） | **切 CSS 渲染器**（还在动） |
| WebGL 不可用 | 静态 WebP | 切 CSS 渲染器 |
| 库加载失败 | 静态 WebP | 切 CSS 渲染器 |
| 移动端 / 弱网 | 静态 WebP | CSS 渲染器（8KB） |
| 运行时抛错 | `console.warn` | 捕获 → 销毁 canvas → 切 CSS 渲染器 |

一句话：**"降级"不再是"变静态"，而是"换更轻的画笔"**。这是我和你原方案最重要的一处分歧。

### 5.8 资源释放

- `onBeforeUnmount` → `widget.destroy()`；
- `visibilitychange` → 暂停/恢复渲染循环；
- 路由切换（Nuxt 页面跳转不销毁 layout）→ 保持实例，只更新状态。

## 附录 · P0 验证结论（2026-11-17 15:20，实测，非推测）

测试环境：本机 Chrome 157（headless `--enable-unsafe-swiftshader` 与**真实窗口**各跑一遍），
极简 CDP 驱动脚本 `_poc/companion/*.mjs`，本地静态服务器 `serve.mjs`，模型从 jsdelivr 拉全。

### 一、官方 API 面（实测 `Object.keys(widget)`）

```
["l2d", "sleep", "switchModel", "destroy"]
```
**确认没有** `sendMessage / showThinking / showToolCall`。所以「气泡自己写」这个决定是对的。

### 二、`l2d-widget@0.1.2`：**moc3 全军覆没**

| 模型 | Cubism 版本 | 结果 |
|---|---|---|
| cat-black（库自带示例，`.moc`） | Cubism 2 | ✅ 正常渲染（透明底、位置正确） |
| Senko_Normals | moc3 ver 2 | ❌ `TypeError: g[y[((n+36)>>2)]] is not a function` |
| Mark | moc3 ver 3 | ❌ 同上 |
| Mao | moc3 ver 5 | ❌ 同上 |

排查过程（都排除了）：
- 不是 WebGL：Cubism 2 同一个 canvas 能画，`WebAssembly.instantiate` 也 OK
- 不是竞态：`delay=3000` 后创建仍报错
- 不是资源缺失：`model3.json` / `moc3` / 贴图全部 200
- 不是 headless 特有问题：**真实窗口模式下同样失败**
- 外部挂官方核心（`live2dcubismcore.min.js`，5.1.0.0）能解析 moc3（`Moc.fromArrayBuffer` 成功），
  但**库启动时会用自带的 6.0.0.1 核心把它覆盖掉**，随后照旧失败

结论：**这个 0.1.2 构建里用于解析 moc3 的 wasm 是坏的**（Emscripten 函数表未初始化）。
若大肥鱼是 model3（大概率），**这个库不能用**。

### 三、`oh-my-live2d@0.19.3`：moc3 能解析

- `OML2D.loadOml2d({ models: [{ path, scale, position, stageStyle }] })`，全局名 `window.OML2D`
- moc3 + 贴图 + motion **全部 200**，控制台无异常，`onStageSlideIn` 触发（页面出现「加载成功」tip）
- 自建 DOM：`#oml2d-stage`（`position:fixed; z-index:9997`）、`#oml2d-statusBar`（`z-index:9998`）
- ⚠️ **未验证**：自动化环境里舞台区域截图像是空白（无头与真实 GPU 都一样），
  分不清是"参数没调"还是"像素没画出来"。**必须在服务器上用真模型人工看一眼**才能定。

### 四、两条对方案有直接影响的实测事实

1. **容器贴死右下角**：两个库默认都 `right:0; bottom:0`，没有边距。
   必须自己在创建后改内联样式（`el.style.right='24px'`），而不是文档里说的"外层容器 right/bottom"——
   它们直接挂在 `body` 上，外层容器管不到。
2. **典型模型 7.8MB**（Senko：贴图 6MB + moc3 1.6MB）。原方案写"控制在 5MB 以内"偏乐观，
   要么压贴图（1024 档），要么接受首访 8MB。

### 五、由此产生的两个岔路（需要你定）

- **A｜换库**：用 `oh-my-live2d@0.19.3`（vendor 2MB），Live2D 仍是大肥鱼。风险：它的渲染我在自动化环境里没验到像素。
- **B｜先 CSS 后 Live2D**（我推荐）：P1 先把 9 状态机 + CSS 小鱼做成**能上线的动态入口**（8KB、零风险），
  Live2D 挂在同一个状态机后面当可选引擎（`companion.engine: 'css' | 'live2d'`，默认 `css`）。
  等你的模型到位、服务器上肉眼验过，再一行配置切过去。**工期不卡在第三方库上**。

# 十二、P1 落地记录（2026-11-17 下午）

## 12.1 结论先行

最终上线的不是 Live2D，也不是 CSS 小鱼，而是**一张自己渲出来的静态立绘 + CSS 微动**。
原因不是技术做不到（技术已经跑通了，见 12.2），而是**授权**。

## 12.2 Live2D 其实能跑（推翻 P0 的"未验证"）

用户的模型 `D:/cxdownload/Blog/DeepSeek免费公皮/DeepSeek/大肥鱼.model3.json`（DeepSeek-chan）：

- `oh-my-live2d@0.19.3` + 内置 **Cubism Core 5.0.0.0** 能完整解析并渲染，实测出了半身立绘。
- P0 阶段"截图像空白"的**真因有三个，只有第三个是技术问题**：
  1. 等待时间不够 —— 16MB 的 moc3 解析要几十秒，固定等 12 秒必然空白；
  2. `stage` 被日志区推到视口外 —— 截图截的是可视区，模型在 y=693 处，天然拍不到；
  3. `scale` 语义是"相对模型原始尺寸的比例"，`0.45` 会让 4096 贴图级别的模型巨大化，
     只露一角。真正合适的是 **0.05~0.09**。
- 一旦 `scale` 对了，模型正常显示：蓝发、女仆装、鲨鱼鳍耳、鱼尾，**参数全部正常**。

## 12.3 为什么最终没上 Live2D

模型使用须知（`DeepSeek免费 Live2D 模型使用须知.txt`）明确写着：

> ❌ 禁止擅自重新分发模型文件 —— 不得将完整模型文件重新上传至网盘、素材网站或其他平台，供他人直接下载。

而网页 Live2D 的技术前提就是**把 `.moc3` 和贴图发给每个访客**，任何人 F12 都能存下来。
这在条款上等同于"重新分发"，且**没有任何前端技术手段可以规避**（能渲染就能被抓）。

条款允许的是：个人直播/视频/二次创作（需署名），**没有**"放到公开网站当装饰"。

体积是第二个问题，但不是决定性的：
- 原始 61MB（贴图 44MB 是 4096×8192 ×5 + moc3 16MB）
- 贴图缩到 1/2 转 WebP → 3.1MB；缩到 1/4 → 1.13MB（180px 显示看不出差别）
- **moc3 压不动**：gzip 9MB / brotli 6.6MB，是 Cubism 导出的成品，不重新导出降不下来
- 本地首访加载实测 **60~90 秒**

## 12.4 最终方案：静态立绘

**产物**（`blog-web/public/companion/`）：

| 文件 | 尺寸 | 体积 |
|---|---|---|
| `standee.webp` | 174×240 | 17 KB |
| `standee@2x.webp` | 348×480 | 48 KB |
| `standee@3x.webp` | 522×720 | 86 KB |

**生成链路**（`_poc/companion/` 下，不进仓库）：

1. `gen-standee.mjs` —— 用 oh-my-live2d 渲 720×960，`Page.captureScreenshot({omitBackground:true})`
   拿到透明底 PNG。关键参数：`scale=0.18`、`position=[120,160]`、`stageStyle=720×960`。
2. `make-standee.py` —— 修图 + 裁边 + 导出：
   - **修掉鼻梁上的黑色小方块**（模型自带瑕疵部件，VTS 里由某个开关控制，静态导出关不掉）：
     定位深色连通块 → 膨胀 2px → 逐行左右插值填充 → 局部高斯模糊
   - **清掉右下角孤立碎片**（尾巴伸到画框外，裁完边变成悬空小块）：
     用位置判定（x>86%W 且 y>90%H 的画面内不可能有身体）而不是连通域，避免为一个补丁引入 scipy
   - 按 alpha bbox 裁边 + 2% 呼吸空间 → 导 1x/2x/3x WebP

**CSS 补的动效**（`CompanionStandee.vue`）：
呼吸浮动（`translate`，4.4s）、鼠标视线跟随（`transform` 位移 3px + 倾斜 0.8deg，仅 idle/hint）、
思考三点、打盹 Z、done 蹦一下、error 下沉变暗、sleep 压暗变慢。
`translate` 与 `transform` 是**两个独立属性**，正好一个给呼吸一个给视线，互不打架。

**降级**：`<img @error>` → 自动切回 `CompanionCss.vue`（内联 SVG 小鱼，约 4KB），入口不会凭空消失。

**署名**（条款强制要求）：`AiFloat.vue` 输入区下方常驻一行
「形象：大肥鱼 · 原画/拆分 神宫凉子 · 建模 霓虹猫_NeonNeko」。

## 12.5 踩过的坑（下次直接用）

1. **`--window-position=2400,2400` 会让 Chrome 停止渲染** —— 想"不弹窗"把窗口挪到屏幕外，
   结果 canvas 建好了、context 没丢、一个像素都不画。截图验证必须把窗口放在屏幕内。
2. **`Page.captureScreenshot` 默认只截视口** —— `stage` 被前面的内容推下去后永远拍不到。
   要么 `captureBeyondViewport: true`，要么给 stage 加 `position:fixed`。
3. **透明底截图要两步**：`Emulation.setDefaultBackgroundColorOverride({a:0})` + `captureScreenshot({omitBackground:true})`，
   少一个都会得到米色底。
4. **这个模型没有内置动作**（作者只导出了 moc3/physics，`FileReferences` 里没有 `Motions`/`Expressions`），
   参数停在默认值。VTube Studio 里靠摄像头追踪驱动，网页里要自己给。
5. **库的实例结构不稳定**：`inst.models[0]` 一直是配置而不是运行实例，
   要拿 Cubism 的 coreModel 只能**深度遍历**（`__coreModel()` 里那段 walk）。
6. **中文路径在这个项目里能用**，但导出产物统一改成 ASCII 文件名（`standee.webp`），免得线上 URL 编码出岔子。
