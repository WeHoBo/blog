# 编辑器预览数学公式不渲染：原因分析与修复报告

> 时间：2026-09-20
> 现象：在编辑器左侧写 `$|f(x)|\le M$`，右侧预览把它当**纯文本**原样显示，没有渲染成数学符号。
> 结论：markdown-it **核心本身不解析 LaTeX**，而项目从未挂过数学插件。已引入 `@vscode/markdown-it-katex` + `katex` 修复，**编辑器预览、文章详情页、AI 问答三处同时生效**。

---

## 一、原因：markdown-it 只负责 CommonMark，不认识 `$...$`

### 1.1 根子在哪

`components/MarkdownRenderer.vue` 里用 markdown-it 渲染正文，插件只挂了两个：

```ts
const md = new MarkdownIt({ html: false, linkify: true, typographer: true, breaks: true })
  .use(markdownItFootnote)     // 脚注
  .use(markdownItTaskLists)    // 任务列表
```

- `markdown-it-footnote`：脚注
- `markdown-it-task-lists`：`- [x]` 任务列表

**没有任何一个负责数学公式。** markdown-it 的设计是"核心只实现 CommonMark 规范"，`$` / `$$` 属于扩展语法，必须靠插件补。CommonMark 规范里 `$` 本来就是个普通字符。

所以 `$|f(x)|\le M$` 被 lexer 当成一串普通文本 → 输出 `<p>设 $|f(x)|\le M$ 恒成立。</p>`。

### 1.2 实测证据（不是推测）

用项目真实的 markdown-it 配置跑一遍，**不加插件**的输出：

| 输入 | 输出 |
|---|---|
| `设 $|f(x)|\le M$ 恒成立。` | `<p>设 $|f(x)|\le M$ 恒成立。</p>` ← 原样 |
| `已知$E=mc^2$成立。` | `<p>已知$E=mc^2$成立。</p>` |
| `$$\n\int_0^1 x^2\,dx = \frac{1}{3}\n$$` | `<p>$$<br> \int_0^1 x^2,dx = \frac{1}{3}<br> $$</p>` |

注意第三行：连 `\frac` 里的反斜杠都被吃掉了（`\f` 被当成转义），说明它完全没走数学解析，只是普通文本 + 转义处理。

### 1.3 一个容易被忽略的关键点：预览和正文是**同一个组件**

编辑器预览处写的是：

```vue
<MarkdownRenderer :content="form.contentMd" />
```

也就是说 **编辑器预览、文章详情页正文、AI 问答气泡三处共用同一个 `MarkdownRenderer`**。所以在 `MarkdownRenderer` 里补齐插件，三处会**一起修好**，不需要分别改。反过来说，之前这三处是**一起坏的**。

## 二、方案选型（两个候选都实测过）

| | `@vscode/markdown-it-katex` ✅ 选它 | `markdown-it-texmath` |
|---|---|---|
| 维护方 | VS Code 团队（VS Code 内置 Markdown 预览同款） | 社区个人 |
| 输出结构 | `<span class="katex">…</span>`，行间为 `<p class="katex-block">` | 额外套 `<eq>` / `<eqn>` / `<section>` **自定义标签** |
| 与现有 CSS 相处 | 干净，只有 katex 自己的类名 | `<section>` 是块级元素，需要额外保证样式 |
| `$…$` / `$$…$$` | ✅ | ✅ |
| 依赖 | 自带 `katex` 依赖 | 需自己传 `engine: katex` |

两者在 `$…$`、`$$…$$`、中文紧贴、下标分式上都实测通过；**差别就是输出干净程度**，所以选了 `@vscode/markdown-it-katex`。

> 顺带一提：`markdown-it-katex`（不带 scope 的老包）不推荐 —— 早已停更，且对行内代码里的 `$` 处理有历史 bug。

## 三、具体改动

### 3.1 依赖（`package.json` / `package-lock.json`）

```
katex                      ^0.16.47   ← 渲染引擎（同时提供 CSS）
@vscode/markdown-it-katex  ^1.1.2    ← markdown-it 插件
```

（中途装过 `markdown-it-texmath` 用于对比，比对完已卸载，依赖树保持干净。）

### 3.2 `components/MarkdownRenderer.vue`

注册插件：

```ts
.use(markdownItTaskLists)
// throwOnError:false —— 公式写错时只在原位渲染一段红色错误提示（KaTeX 自带），
// 绝不能让它抛异常：md.render() 一抛，整篇正文的 HTML 就全没了。
.use(markdownItKatex, { throwOnError: false, errorColor: '#cc0000' })
```

并且**解包了 CJS 互操作的坑**（见下）。

### 3.3 ⚠️ 踩到并修掉的一个真坑：CJS 双包装

`@vscode/markdown-it-katex` 是**纯 CJS 包**（只有 `main`，没有 `exports`/`module` 字段），而项目里现成的 `highlight.js`、`markdown-it` 都有 ESM 入口 —— **没有先例**。

它内部写了 `exports.default` + `__esModule`，于是"默认导出"是什么，取决于谁加载：

| 加载方 | `import x from '...'` 拿到的东西 |
|---|---|
| Vite 打包（客户端） | 直接是插件函数 ✅ |
| Nitro SSR 把依赖外置、交给 **Node 原生 ESM** | `{ default: fn }` 一层包装 ❌ |

实测：纯 Node ESM 下 `typeof markdownItKatex === 'object'`，直接 `.use()` 会抛
`TypeError: plugin.apply is not a function` —— **服务端渲染会直接 500**。

修复：改成命名空间导入 + 手动剥一层，两种形态都吃得住。

```ts
import * as markdownItKatexModule from '@vscode/markdown-it-katex'

const markdownItKatex: any = ((): any => {
  const mod: any = markdownItKatexModule
  if (typeof mod === 'function') return mod
  if (typeof mod?.default === 'function') return mod.default
  return mod?.default?.default
})()
```

### 3.4 `nuxt.config.ts`：KaTeX 样式走全局引入

```ts
// 公式在 SSR 阶段就已渲染成 HTML，样式若晚到，首屏会出现「先错乱、再抖正」的闪动
css: ['katex/dist/katex.min.css'],
```

字体路径由 Vite 重写，字体文件随构建产物一起拷贝。

### 3.5 `assets/css/main.css`：两行适配

```css
/* 行间公式过宽时横向滚动，而不是把卡片撑破 */
.article-content .katex-display { overflow-x: auto; overflow-y: hidden; padding: 4px 0; }
/* 公式写错时 KaTeX 会把报错原文染红渲染出来 */
.article-content .katex-error { color: #cc0000; }
```

**颜色刻意不写死**：KaTeX 自身不设 `color`，公式跟着正文继承，浅色/夜间模式自动适配，不需要额外的 `.dark` 覆盖规则。

### 3.6 为什么用静态 import，而不学 mermaid 放 `public/vendor`

mermaid 是**运行时**在 DOM 上画图，SSR 出不来也无所谓，所以它放 `public/vendor` 按需加载。

数学公式不一样：**它必须参与 SSR**。文章详情页是服务端渲染的，公式要在服务端就变成 HTML，否则首屏会先闪一下 `$|f(x)|\le M$` 原文（也就是用户现在看到的那个样子）再跳成公式。动态 `import()` 拿不到同步结果，所以这里用静态引入。

## 六、部署步骤（服务器）

> ⚠️ `package.json` 和 `package-lock.json` 都变了，**必须重新 `npm ci`**，否则构建时找不到 katex。

```bash
cd /opt/blog/blog-web
git pull
npm ci                 # 必须！新增了 katex / @vscode/markdown-it-katex
npm run build
sudo rm -rf /opt/blog/web/.output
sudo cp -r .output /opt/blog/web/.output      # 整个 .output，不只是 public
sudo systemctl restart blog-web
```

**后端无需改动、无需重启**（markdown 渲染全在前端，后端只存 `content_md`）。

### 顺带一提：字体文件
KaTeX 会带 60 个字体文件（woff2/woff/ttf 合计约 1.2MB）进构建产物。浏览器靠 CSS 的 `unicode-range` **只下载实际用到的几个**，不会全拉；但磁盘占用是实打实的。如果想瘦身，可以只保留 `woff2`（现代浏览器全覆盖），能砍掉约一半。

## 七、自测清单

编辑器里依次粘贴，看右侧预览：

1. 行内：`设 $|f(x)|\le M$ 恒成立。` → 应显示为数学符号，且**看不到 `$` 和 `\le`**
2. 紧贴中文：`已知$E=mc^2$成立。` → 同样渲染
3. 行间：单独一行写 `$$\int_0^1 x^2\,dx = \frac{1}{3}$$` → 居中大号公式，**过宽时能横向滚动**
4. 下标分式：`有 $a_1=\frac{b}{c}$ 成立。` → 下标与分式正确
5. **不该渲染的别渲染**：`价格是 `$5` 美元`（行内代码）→ 保持原样
6. **不该渲染的别渲染**：`花掉 \$100`（转义）→ 保持原样
7. 代码块里写 `const a = "$x$"` → 代码块内原样，不被公式化
8. 公式写错（如 `$\frac{1}{$`）→ **页面正常显示**，只有那一处变红提示，不能整页崩掉
9. 回归：脚注 `[^1]`、任务列表 `- [x]`、标题、代码高亮复制按钮 → 均正常
10. 发布后打开文章详情页 → **首屏直接是公式**，不能先闪一下 `$...$` 原文
11. 切换到夜间模式 → 公式颜色跟着变浅，清晰可读
12. 打开一次 AI 问答，让回答里带公式 → 同样渲染

## 九、遗留 / 可选后续

1. **关于页（`about.vue`）不支持公式** —— 它是独立的 `MarkdownIt` 实例。若你想让"关于"页也能写公式，说一声即可，改法一样。

3. **未跑完整 `nuxi build`** —— 沙箱会拦批量删除。静态检查 + Node 侧渲染实测都过了，但真实构建仍需在服务器上验证一次。
