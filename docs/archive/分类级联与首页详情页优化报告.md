## 一、分类相关修复

### 1.1 一级分类删除后，二级分类没有跟着删（级联删除）

**问题**：原 `CategoryController.delete()` 只删当前这条分类，并把**直属**文章的分类置空：

```java
articleMapper.update(null, ... .eq(categoryId, id).set(categoryId, null));
categoryMapper.deleteById(id);   // ← 只删了自己
```

结果：删掉一级分类后，它下面的二级分类**还在**，但 `parent_id` 指向一条已经不存在的记录 —— 在分类树里会漂浮成"一级分类"，成为孤儿数据。

**修复**：先把整棵子树收集出来，再一次性处理。

```java
List<Long> ids = collectSubtreeIds(id);            // 广度优先，含自身 + 所有子孙
articleMapper.update(... .in(categoryId, ids).set(categoryId, null));  // 子树下文章统一置空
categoryMapper.deleteBatchIds(ids);                // 整批删除
```

`collectSubtreeIds()` 一次性把全部分类查进内存建 `children` 索引（避免按层递归的 N+1 查询），用 `visited` 集合同时承担"防重复入队"和"防御脏数据的父子环"两个职责。

**顺带加固**：内置分类「未建档文章」不允许删除（它是无分类文章的兜底归属，删掉语义就崩了），返回明确提示。

### 1.2 后台分类管理的删除入口

后台 `/admin/categories` 的删除按钮**本来就存在**（一级、二级分类行各有一个）。本次做了两处修正：

1. **确认文案改对了**：原来写的是"子分类不会被删除"，现在改成
   > 确定删除该分类吗？其下【所有子分类会一并级联删除】，这些分类下的文章会变为「未建档文章」。此操作不可撤销。

2. **修掉一个静默失败隐患**（见下），让"删不掉"这类情况能如实报错。

> **⚠️ 顺带发现的一个通用坑**
> `composables/useApi.ts` 只在 **HTTP 状态码异常** 时抛异常，而后端 `GlobalExceptionHandler` 处理 `BusinessException` 时**没有 `@ResponseStatus`** → 返回的是 **HTTP 200 + body.code=400**。
> 也就是说：**凡是"业务失败"（文章不存在、别名冲突、内置分类不可删除……），前端 `try/catch` 根本抓不到**，会一路走到"保存成功/删除成功"。
> 本次在 `admin/categories.vue` 的 `handleSave` / `handleDelete` 里补了 `res.code !== 200` 判定。**其它后台页面同样存在这个隐患，建议后续统一处理**（要么后端给业务异常加正确的 HTTP 状态码，要么前端封装一层）。

## 二、文章没设分类 → 自动归入「未建档文章」

### 2.1 设计

新增常量类 `CategoryConstants`：

| 常量 | 值 | 说明 |
|---|---|---|
| `DEFAULT_CATEGORY_NAME` | `未建档文章` | 写死的分类名，前台展示兜底也用它 |
| `DEFAULT_CATEGORY_SLUG` | `uncategorized` | 固定 slug（`slug` 上有唯一键，用来防并发重复建） |
| `DEFAULT_CATEGORY_SORT` | `9999` | 排序值给大数，保证排在所有人工分类之后 |

**为什么落到真实分类行，而不是只在展示层兜个名字？**
分类页的文章数是按 `category_id` 聚合算出来的（`countPublishedByCategory`）。只兜名字的话会出现"**列表里显示有这个分类、点进去却是空的**"这种自相矛盾。写进库才能数得对、点得进去。

### 2.2 三层保障

1. **保存时归属**（`ArticleService`）—— `create` / `update` / `importMd` / `importWord` / `restoreRevision` 五个写入点，只要 `categoryId` 为空，就调 `defaultCategoryId()` 拿到内置分类 id 再落库。
   - `defaultCategoryId()`：先按固定 slug 找 → 再按名字找 → 都没有才创建；并发撞唯一键时回查一次兜底。
2. **展示层兜底**（`ArticleController.list`）—— 历史数据万一还是 `null`，`categoryName` 统一回落到「未建档文章」，列表里永远不会出现空白分类。
3. **启动时回填**（`DefaultCategoryInitializer`，`ApplicationRunner`）—— 启动时确保内置分类存在，并执行一次幂等 UPDATE：
   ```sql
   UPDATE article SET category_id = ? WHERE category_id IS NULL
   ```
   实测线上只有 **1 篇**未分类文章，回填零风险。这条刻意**不**中断启动（失败只记 warn），和 `WordCountMigrator` 的"必须快速失败"策略不同 —— 那条是表结构缺失会让所有查询 500。

**管理员手动设了分类就以管理员为准**：`dto.categoryId != null` 时直接用管理员选的值，只有为空才走内置分类。

## 三、首页顶部信息框：中间 / 右侧不再留白

原 Hero 只有左侧一段文字，右侧一大片空白。现在改成 **lg 三栏栅格**（`lg:grid-cols-[1.5fr_1fr_1.1fr]`），窄屏自动堆叠：

| 栏位 | 内容 |
|---|---|
| 左 | 「你好，我是好啵 👋」+ 副标题 + **关注方向** chips（Java/AI/Python/Linux/Docker）+ 开始阅读 / 关于我 |
| 中 | **站点概览**：文章数 / 分类数 / 标签数（`siteStats`） |
| 右 | **热门标签** 前 6 个（可点击，走 `taxonomyPath`）+ 「全部分类 →」 |

- 数据全部复用首屏已有的 SSR payload（顺手用了已发出的 `/article/list?pageSize=5` 里的 `total`），**没有新增任何接口请求**。
- 三栏之间用 `border-l` 轻分隔，保持与主题色/暗色模式一致。

## 五、文章详情页：封面改成标题右侧的方形缩略图

**改前**：标题 → 元信息 → **通栏大封面（`w-full max-h-96`）** → 正文。又长又扁，把标题和正文硬生生隔开一大段，长条比例和左侧密集文字也不协调。

**改后**：左「标题 + 元信息」／右「约方形封面缩略图」两栏对齐。

```
┌──────────────────────────────────────────────┬───────────┐
│  408_数据结构核心代码与逻辑速记                 │           │
│                                              │  方形封面  │
│  2026-09-18 · 👤好啵 · 👁7 阅读                │  缩略图    │
│  📝1913 字 · ⏱4 分钟阅读 · 💬0 评论            │           │
└──────────────────────────────────────────────┴───────────┘
```

- 缩略图尺寸响应式：`w-20 h-20` → `sm:w-28 sm:h-28` → `lg:w-32 lg:h-32`，`rounded-2xl` + 细描边 + 轻阴影。
- 六项元信息**统一置于标题下方**，顺序按你给的：发布时间 → 发布人 → 阅读人数 → 字数 → 阅读时间 → 评论人数（`AI 总结` 按钮仍在同一行末尾）。
- 用 `items-start` 让缩略图与标题顶部对齐，避免"标题长、图居中"的错位感。

## 九、自测清单

**分类级联删除**
1. 后台新建 一级分类 A → 其下建 二级分类 B → B 下建 三级分类 C
2. 删除 A → 确认框应写明"所有子分类会一并级联删除"
3. 删除后：A / B / C **全部消失**；原先属于它们的文章分类变成「未建档文章」
4. 尝试删除「未建档文章」→ 应提示"系统内置分类，不能删除"（而不是假装成功）
5. 删除 B（中间层）→ B 和 C 一起消失，A 保留

**未建档文章**
6. 新建文章时**不选分类** → 保存后该文章分类显示「未建档文章」
7. 后台分类侧边栏能看到「未建档文章」并带有正确文章数；点进去能筛出这些文章
8. 手动给文章选一个分类 → 显示所选的分类

**首页**
9. 首页顶部横幅：中间有「文章/分类/标签」三个数字，右侧有热门标签 chips（可点击跳转）
10. 窄屏（手机）下三栏自动堆叠，不溢出

**导航栏**
11. 桌面导航「标签」右侧**不再有调色盘图标**
12. 登录后右上角头像 → ⚙️ 设置 → 仍能打开主题设置弹窗并调色

**文章详情页**
13. 打开任一有封面的文章：封面是**标题右侧的方形缩略图**，不再是通栏大图
14. 标题下方依次是：发布时间 · 发布人 · 阅读 · 字数 · 阅读时间 · 评论
15. 无封面的文章排版不塌陷（右侧留空，左侧正常）
16. 手机端同样呈现"左信息 + 右小方图"，不挤压标题
