# 文章展示不一致修复 + 推荐增强 变更报告

> 时间：2026-09-12
> 涉及端：`blog-web`（Nuxt 3 前端）、`blog-server`（Spring Boot 后端）、`rag_system`（Python RAG）
> 目标：**同一篇文章，无论从哪个入口进来，看到的页面完全一致**；并补齐 GitHub 入口与相关推荐。

---

## 一、问题排查：为什么「首页入口」和「RAG 入口」看到的不一样

### 1.1 现象

- `https://codeup.asia/article/73` 这类页面：**有**评论、上一篇/下一篇、相关推荐、作者卡片、左侧目录。
- 从首页 / 归档页点进去的同一篇文章：**没有**上面这些模块，只剩标题 + 正文 + 标签。

### 1.2 定位：两处文章渲染逻辑的差异

这个项目里"文章详情"实际存在**两个页面文件**，早期分别写了两套模板：

| 页面文件 | 路由 | 功能 |
|---|---|---|
| `pages/article/[id].vue` | `/article/{id}` | **完整版**：目录、作者卡、评论、上/下篇、相关推荐 |
| `pages/post/[slug].vue` | `/post/{slug}` | **精简版**：只有标题 + `MarkdownRenderer` 正文 + 标签 |

也就是说，功能差异不来自"数据"，而来自**页面文件本身是两份不同的代码**。

### 1.3 根因：入口不同 → 命中了不同的路由

前端各处生成文章链接的写法不统一：

```ts
// 首页 / 归档 / ArticleCard 等列表入口
:to="a.slug ? `/post/${a.slug}` : `/article/${a.id}`"   // slug 优先 → /post/{slug}（精简版）
```

```python
# rag_system/backend/vector_store.py：RAG 命中的来源链接
hit["url"] = f"/article/{article_id}"                   # 固定指向 /article/{id}（完整版）
```

于是：

- 首页 / 归档 / 文章卡片 → 只要有 slug 就走 `/post/{slug}` → **落进精简版页面** → 缺模块；
- RAG 问答里点来源 → 走 `/article/{id}` → **落进完整版页面** → 模块齐全。

**同一篇文章，因为入口不同命中了两个不同的路由文件，这就是"展示不一致"的根本原因。**
（第 73 篇正好有 slug，所以从首页进就是缺模块的那个版本。）

> 补充：早期 `/post/{slug}` 是"SEO 友好 + 正文够用"的取舍，但后续给 `/article/{id}` 加了评论、推荐等交互功能后，**没有同步回填到 `/post/{slug}`**，两份模板就此分叉。

### 1.4 修复方案：双路由统一到同一个渲染组件

思路上不再"维护两份模板"，而是**抽出一个唯一真相源组件，两个路由都渲染它**：

```
pages/article/[id].vue  ─┐
                         ├─►  components/ArticleDetail.vue   （唯一实现：目录/评论/上下一篇/推荐/作者卡）
pages/post/[slug].vue   ─┘
```

同时**统一所有文章链接的生成方式**，杜绝"有的写 /post、有的写 /article"：

```ts
// blog-web/utils/articlePath.ts  —— 唯一入口
export function articlePath(a) {
  const slug = typeof a?.slug === 'string' ? a.slug.trim() : ''
  if (slug) return `/post/${encodeURIComponent(slug)}`   // 有 slug 走规范化 URL
  return a?.id != null ? `/article/${a.id}` : '/'        // 无 slug 回退
}
```

所有列表入口（`index.vue`、`ArticleCard.vue`、`archive.vue`）以及详情页内部的上/下篇、相关推荐，全部改走 `articlePath()`。

**RAG 侧对齐**：`vector_store.py` 让来源链接 slug 优先，和前端保持同一套规则：

```python
_slug = str(meta.get("slug") or "").strip()
hit["url"] = f"/post/{_slug}" if _slug else f"/article/{meta.get('article_id')}"
```

### 1.5 修复后效果

| 入口 | 路由 | 渲染结果 |
|---|---|---|
| 首页 / 归档 / 文章卡片 | `/post/{slug}` | ✅ 完整（走 `ArticleDetail`） |
| RAG 来源 / 直接访问 id | `/article/{id}` | ✅ 完整（走 `ArticleDetail`） |
| 新增：无 slug 的老文章 | `/article/{id}` | ✅ 完整（回退路由） |

两个入口现在**共享同一份组件**，功能再也不会分叉。

## 三、新增功能二：相关推荐补齐 + 后端推荐逻辑修复

### 3.1 后端：相关推荐"时有时无"的 Bug

原 `ArticleService.related()` 只在 **`categoryId` 非空、且同分类下还有其它文章**时才返回数据。

后果：
- **未分类的文章** → `categoryId == null` → 直接返回空 → 文末推荐区**整块消失**；
- **分类下只有 1 篇文章** → 同分类没有别的文章 → 同样返回空。

**修复**：不足 4 篇时，**用最新文章补齐**（排除自己 + 已选中的），保证推荐区永远有内容：

```java
// 1) 先取同分类其它文章（最多 4 篇）
// 2) 不足 4 篇 → 从全站最新文章里补齐，notIn 排除自己与已选
// 3) 列白名单：只查 id/title/slug/cover/summary/viewCount/createTime，不带 content_md/content_html
```

`recommendBase()` 单独抽出列白名单查询，避免把 LONGTEXT 正文一起拉出来（4 篇推荐白白带几百 KB）。

### 3.2 前端：相关推荐卡片升级

卡片从"只有标题 + 日期"升级为**完整卡片**：

- 封面缩略图（`cover`，无图时占位）
- 摘要（`summary`，截断一行）
- 阅读数（`viewCount`）+ 发布日期
- 标题区右上角新增 **「更多文章 →」**，链接到 `/archive`，给读者一个明确的下一步出口

所有推荐卡片链接同样走 `articlePath()`，与详情页一致。

## 六、部署步骤（服务器）

### 1. 后端（改了 `ArticleService.java`，需重新打包）
```bash
cd /opt/blog/blog-server
git pull                      # 若服务器侧也是 git 部署；否则手工同步 jar
# 重新打包（服务器有 maven 时）
mvn -q -DskipTests clean package -pl blog-front-api -am
# 替换 jar 并重启（注意 jar 落地名要与 service 中一致！）
sudo cp blog-front-api/target/blog-front-api-1.0.0.jar /opt/blog/blog-api.jar
sudo systemctl restart blog-front-api
```

### 2. 前端（改了多个 `.vue` + 新增 `utils/`、`components/`）
```bash
cd /opt/blog/blog-web
git pull
npm ci && npm run build       # 产出整个 .output
sudo rm -rf /opt/blog/web/.output
sudo cp -r .output /opt/blog/web/.output
sudo systemctl restart blog-web
```
> ⚠️ 必须部署**整个 `.output`**（不是只拷 `.output/public`），否则新增页面/组件不会生效。

### 3. RAG（改了 `vector_store.py`）
```bash
cd /opt/blog/rag_system
sudo systemctl restart rag-api   # 或对应服务名
```
> 仅改来源 URL 生成逻辑，**无需重建向量库**；对已入库的历史数据，旧命中的 url 字段若已写死需重新入库或前端做兼容（前端 `AiFloat` 已用 `s.url || '#'` 兜底）。

### 4. Nginx
本次无需改 Nginx 配置。

## 八、回滚

- 前端：`git revert` 对应提交，或还原 `.output` 为上一版备份；重启 `blog-web`。
- 后端：还原 `/opt/blog/blog-api.jar` 为旧 jar，`systemctl restart blog-front-api`。
- RAG：还原 `vector_store.py` 后重启服务。
- 三端**互不阻塞**，可单独回滚（后端推荐为空只会影响推荐区，不会导致页面报错）。
