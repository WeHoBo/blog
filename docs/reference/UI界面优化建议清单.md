## 一、全站框架层

### 1.1 页面布局 `layouts/default.vue`

**问题**
1. **常驻动画开销大**：鼠标拖尾 canvas 的 `animate()` 是无限递归 `requestAnimationFrame`，即使鼠标静止也不停；每帧还在算彩虹色。加上鼠标跟随光斑、星空背景、节日特效，笔记本/手机上持续耗电。`layouts/default.vue:76-88`
2. **内存泄漏**：拖尾的 `mousemove` 监听是匿名函数，卸载时**无法移除**；`animate()` 也没有取消入口。`layouts/default.vue:72-75`
3. **背景图先空后闪**：`bgImage` 只在 `onMounted` 里客户端请求 `/site-config/public`，SSR 拿不到 → 先渲染星空、再切成背景图，首屏有一次明显闪动。`layouts/default.vue:59-64`

**优化方向**：动画统一挂到"用户是否偏好减少动效"开关下；`animate()` 用 `document.hidden` 或空闲检测暂停；监听器改用具名函数并保存引用；背景图改为 `useAsyncData` 走 SSR（或直接用 `useSiteConfig` 组合式函数，见 4.4）。

**预期收益**：移动端耗电与发热明显下降；首屏不再闪；切换页面不再泄漏监听器。

**优先级**：P1

### 1.2 顶部导航 `components/Header.vue`

**问题**
1. **下拉菜单不会点外关闭**：用户菜单只有点击自己的按钮才收起，点页面空白处不关，Esc 也不关。`Header.vue:42-56`
2. **设置弹窗无障碍缺失**：没有 `role="dialog"` / `aria-modal`、没有 Esc 关闭、没有焦点陷阱与初始焦点。`Header.vue:88-144`
3. **弹窗关闭按钮用 `✕` 字符**、汉堡按钮用 `☰`/`✕` 字符，没有 `aria-label`；Logo 翻转是 `@mouseenter` 触发的，**键盘用户永远看不到**。`Header.vue:9,63,67,93`
4. **"模块背景颜色"滑块使用极宽泛的全局选择器**：注入的 `<style>` 用 `[class*="bg-white"] { background-color: X !important }` 覆盖一切，会连弹窗、编辑器工具栏、代码块一起染色，且 `.dark .bg-white` 也被强制改成浅色。`Header.vue:240-245`
5. **主题色只有一个 0–360 裸滑块**，没有预设色卡，普通用户很难调出好看的颜色。`Header.vue:103`

**优化方向**：加统一的 `v-click-outside` + Esc 关闭；弹窗补全 dialog 语义与焦点管理；图标按钮补 `aria-label`，Logo 翻转加 `@focus`；背景色方案改为在**主题层**（CSS 变量）做，而不是 `!important` 覆盖工具类；主题色加 6–8 个预设色块。

**预期收益**：交互不再"卡住不关"；键盘/读屏可用；背景调色不再引发意外串色。

**优先级**：P1（其中弹窗无障碍 P1，背景色选择器 P1，色卡 P2）

### 1.3 页脚 `components/Footer.vue`

**问题**
1. 只有版权和 ICP 备案号，**没有站内导航、没有 RSS、没有社交入口** —— 页脚是 SEO 与二次导流的黄金位置，现在完全浪费。`Footer.vue:1-9`
2. 技术博客的读者**普遍期待 RSS 订阅**，目前没有 `/rss.xml` 或 `/feed` 入口。

**优化方向**：页脚加两栏（热门分类 / 快捷入口）、RSS 图标、最近更新时间；RSS 可由后端或 Nitro 路由生成。

**预期收益**：内链权重提升；老读者可订阅；页脚不再像半成品。

**优先级**：P1（RSS P1，页脚导航 P2）

### 1.4 反馈组件 `AppToast.vue` / `AppConfirm.vue`

**问题**
1. **Toast 会被顶部导航挡住**：容器定位 `top-4 right-4`，而导航是 64px 高的固定条；Toast 的 `z-[100]` 高于导航，于是提示会压在导航上。`AppToast.vue:2` vs `Header.vue:2-6`
2. **确认框 Esc 实际不生效**：`@keydown.esc` 绑在一个不可聚焦的 `div` 上，焦点没进弹窗，键盘事件到不了它。`AppConfirm.vue:9`
3. **没有危险态**：`confirmDialog(message, title='确认操作')` 只有一种样式，删除类操作的确认按钮是主题蓝而不是红色，标题永远叫"确认操作"。`useFeedback.ts:52`
4. **只有颜色区分成败**：没有 ✓/✕ 图标；错误也用 `role="status"`（应为 `role="alert"`）。`AppToast.vue:2,8`

**优化方向**：Toast 下移到 `top-20`；确认框打开时自动聚焦按钮 + 焦点陷阱 + 修 Esc；`confirmDialog` 增加 `variant: 'danger'` 参数；成功/失败加图标并区分离散度（assertive/polite）。

**预期收益**：提示不被遮挡、可键盘操作、危险操作视觉上"有分量"。

**优先级**：P1

## 二、读者端页面

### 2.1 首页 `pages/index.vue`

**问题**
1. **分页 / 分类 / 标签状态都不进 URL**：`pageNum`、`currentCategory` 是组件内 ref，刷新或分享链接就回到第一页"全部文章"。`index.vue:282-285, 145`
2. **翻页后停留在页面底部**：点"下一页"后不回到列表顶部，用户得手动滚上去。`index.vue:145`
3. **骨架屏与真实卡片不一致**：骨架是 `rounded-lg` 5 条，真实卡片是 `rounded-2xl` 且每页 15 条 → 内容出现时整体跳动。`index.vue:108-122` vs `ArticleCard.vue:3`、`index.vue:390`
4. **Hero 区的技术标签是硬编码**：`['Java','AI','Python','Linux','Docker']` 与真实分类无关。`index.vue:11`
5. **Hero 的"开始阅读"用 `href="#articles"`**，同样会被固定头部遮挡（见 2.2 第 3 条）。`index.vue:14`
6. **SEO 摘要写死**：`useSeoMeta` 的 description 是硬编码字符串，后台「站点描述」改了也不生效（见 3.6）；`canonical` 恒指向首页，搜索/分类页无法被收录。`index.vue:461-469`

**优化方向**：页码/分类/标签同步到 query（`?page=2&cat=3`）并监听回填；翻页后 `scrollIntoView` 到列表顶部；骨架屏对齐成与卡片同圆角、同条数（8–15 条）；Hero 标签改从真实分类取前 5；锚点加 `scroll-margin-top`；description 改读站点设置，分类/标签页给独立 canonical。

**预期收益**：可分享、可刷新、可回退；不再跳动；Hero 与真实内容一致。

**优先级**：P1（分页进 URL、翻页回顶、骨架一致）；P2（Hero 标签、SEO 细化）

### 2.2 文章详情页（`pages/article/[id].vue` 与 `pages/post/[slug].vue`）

> ⚠️ 这是全站**最严重**的界面问题。

**问题**
1. **两个入口的功能严重不对等**。`/post/{slug}` 是 canonical 规范页、也是首页卡片默认跳转目标，但它只有 **82 行**，缺少：封面图、目录、标签、作者信息、阅读时长、字数、AI 总结、上下文选中解释、上一篇/下一篇、评论、相关推荐、复制链接。而"非规范"的 `/article/{id}`（379 行）全都有。`post/[slug].vue:1-30` vs `article/[id].vue:1-156`
   → **结果**：从搜索引擎或首页进来的读者（绝大多数）看到的是一个"半成品文章页"，没有评论、没有相关推荐、没法继续读下去。
2. **正文没有行长约束**：`<article>` 没有 `max-w-*`，容器是 `max-w-7xl`(1280px)，减去 224px 目录和 24px 间距与 80px 内边距，正文宽约 **950px**，中文一行能排到 **近 60 字**，远超阅读舒适区（约 35–45 字）。而紧邻的"上一篇/下一篇"却用了 `max-w-3xl`。`article/[id].vue:19, 66`
3. **锚点跳转被固定头部遮挡**：全站没有任何 `scroll-margin-top`，点目录或"开始阅读"后标题会藏在 64px 的固定导航下面。`grep scroll-margin` 全仓为空
4. **目录只在桌面端有**：`hidden lg:block`，手机上长文**完全没有目录**。`article/[id].vue:5`
5. **评论区功能薄**：只拉最近 50 条、**无分页**；无回复/楼中楼、无点赞、无删除自己的评论、不支持 Markdown、评论者无头像；输入框显示 `x/500` 却**没有 `maxlength`**，超长只能等后端报错。`article/[id].vue:111-133, 287`
6. **列表页三个区块的内部链接不一致**：上一篇用 `/article/{id}`，下一篇用 `slug ? /post/{slug} : /article/{id}`，相关推荐又一律 `/article/{id}` —— 与项目约定的"内部链接一律走 slug"相悖，制造重复抓取路径。`article/[id].vue:67, 72, 145`
7. **上下文"AI 解释这段"在手机上等于失效**：只监听 `document` 的 `mouseup`，触屏选中不会触发。`article/[id].vue:203`
8. **该工具条并不校验选区是否在正文内**：注释写着"跨出正文区域不显示"，代码只判断了长度，选中导航/评论里的文字也会弹出。`article/[id].vue:211-223`
9. **工具条没有边界处理**：`top: rect.top` 直接定位，选中靠近视口顶部时会飞出屏幕。`article/[id].vue:163`
10. **加载态是转圈而非骨架**，错误态是死文案、没有重试按钮也没有返回首页入口。`article/[id].vue:12-18`
11. **封面图没有宽高**，图片加载时发生布局位移（CLS）。`article/[id].vue:46`
12. **封面/头像有 3 处 `<img>` 没有 `alt`**。`article/[id].vue:28, 89`、`profile.vue:10`
13. **AI 总结需要登录**，但右下角的 AI 助手不需要 —— 同一个能力两套门槛。`article/[id].vue:35`
14. **后端有 `series`（系列）字段但界面完全没有呈现**，读者无法沿系列连续阅读。

**优化方向**
- **最高优先**：把 `post/[slug].vue` 与 `article/[id].vue` 合并成同一个文章详情组件（差异只在"如何取数据"），两条路由共用一套 UI。这是本次收益最大的一步。
- 正文加 `max-w-prose`/`max-w-3xl` 并居中；加全局 `scroll-margin-top: 5rem`。
- 移动端目录：右上角浮动的"目录"按钮 + 抽屉。
- 评论：加分页/加载更多；补 `maxlength="500"` 与字数接近上限时的提醒；后续再考虑回复与点赞。
- 统一所有内部链接走 slug 版 URL。
- 选中工具条改为 `pointerup` + 选区包含性校验 + 视口边界钳制。
- 加载态换骨架屏，错误态加"重试"与"返回首页"。
- 封面图补 `width/height`（或 `aspect-ratio`）与 `alt`。

**预期收益**：绝大多数访客的阅读路径从"半成品"变成完整；正文可读性显著提升；评论区不再"只能看 50 条"；不再制造重复 URL。

**优先级**：**P0**（第 1、2、3 条）；P1（4–12）；P2（13、14）

### 2.3 目录 `components/TableOfContents.vue`

**问题**
1. **同名标题会撞 ID**：两个标题文字相同 → 生成同一个 `id`，`v-for` 的 `:key` 也重复（Vue 会告警），点第二个目录项会跳到第一个。`TableOfContents.vue:5, 40` 与 `MarkdownRenderer.vue:54`（两处算法一致，但都没有去重加后缀）
2. **目录不区分层级**：h1–h4 全收，如果正文以 h1 开头，目录会和文章标题重复。`TableOfContents.vue:36`
3. **IntersectionObserver 与 scroll 监听同时写 `activeId`**，两者判断标准不同，快速滚动时高亮会抖。`TableOfContents.vue:74-86`

**优化方向**：ID 生成加计数器（`标题`、`标题-1`…），**且渲染端与目录端必须共用同一个函数**（建议抽成 `composables/useHeadingAnchor.ts`）；h1 可排除或单列；只保留一套高亮策略。

**预期收益**：长文目录不再"点了没反应"；无重复 key 告警。

**优先级**：P1

### 2.4 正文渲染与代码块 `components/MarkdownRenderer.vue`

**问题**
1. 🔴 **复制代码会丢换行**（已实测）。每行是 `<span class="line">` 且用 `join('')` 拼接，**中间没有任何换行符**；复制按钮读的是 `code.textContent`。
   实测结果：源码
   ```
   public class A {
     int x = 1;
     void f() {}
   }
   ```
   复制得到：`"public class A {  int x = 1;  void f() {}}&nbsp;"` —— **换行数 0（应为 4）**，且末尾空行变成字面量 `&nbsp;`。
   对一个技术博客来说，"复制代码"是最核心的操作之一，这条影响极大。`MarkdownRenderer.vue:38, 96`
2. **手机上没有复制按钮**：按钮 `opacity: 0`，只在 `pre:hover` 时显示，触屏没有 hover。`main.css:169-175`
3. **正文图片不懒加载**：markdown 渲染出的 `<img>` 没有 `loading="lazy"`，长文首屏会一次性请求所有图片。`MarkdownRenderer.vue` 无 image 规则
4. **mermaid 放大遮罩用 `z-50`**，低于 AI 助手按钮（`z-[65]`）和聊天窗（`z-[80]`）→ 放大图时 AI 按钮会浮在遮罩上面；遮罩也没有 Esc 关闭与 dialog 语义。`MarkdownRenderer.vue:113`
5. **外链同标签打开**，技术文章里的参考链接会把读者带走；也没有外链标记。`MarkdownRenderer.vue` 无 `target` 规则
6. **大文档渲染开销**：`md.render` 放在 `computed` 里，编辑器实时预览时每次输入都会全量重渲染 + 重新 `enhance()`，极长文章会卡。

**优化方向**
- 复制改用 **`pre` 上挂一个隐藏的原始文本**（例如把未分行的原文放进 `data-code` 属性），或把行间拼接改为 `\n`；同时去掉 `&nbsp;` 占位（空行保留真空行）。
- 复制按钮在触屏下常显（用 `@media (hover: none)`）。
- 给 image 渲染规则统一补 `loading="lazy" decoding="async"`。
- mermaid 遮罩提到 `z-[90]` 以上，并补 Esc/dialog 语义。
- 外链加 `target="_blank" rel="noopener"` 与一个小图标。
- 编辑器预览侧加输入防抖。

**预期收益**：复制代码立即可用（最高频操作）；移动端能复制；长文加载更快；遮罩层级正常。

**优先级**：**P0**（第 1 条）；P1（2、3、4）；P2（5、6）

### 2.5 文章卡片 `components/ArticleCard.vue`

**问题**
1. **两种布局信息不对称**：列表模式有分类/字数/摘要/阅读数，网格模式只有日期/阅读/评论 —— 且**网格模式没有"置顶"角标**，列表模式也没有。`ArticleCard.vue:15-23, 30-53`
2. **标题字号过大**：列表卡片标题用 `text-2xl`（24px），一屏 5–6 条时视觉噪音很重，压过页面主标题。`ArticleCard.vue:15, 33`
3. **封面图没有宽高**，加载时列表会跳动。`ArticleCard.vue:8, 58`
4. **图片 404 没有兜底**：封面挂了会显示浏览器"裂图"图标，没有 `onerror` 回退到占位图。`ArticleCard.vue:8`
5. **`props` 里声明了 `tags` 和 `author` 但从未渲染** —— 标签本可以帮助读者快速判断内容，是白丢的信息。`ArticleCard.vue:69`
6. 日期用 `createTime.substring(0,10)` 直接切字符串，没有"3 天前"这类相对时间。

**优化方向**：两种布局补齐同一组元信息（分类 + 阅读 + 评论 + 置顶角标）；标题降到 `text-lg`/`text-xl`；图片补尺寸与 `onerror` 占位；把 `tags` 渲染出来。

**预期收益**：列表更易扫读、不再跳动、信息不再浪费。

**优先级**：P1（信息对称、图片兜底）；P2（字号、相对时间、标签）

### 2.6 归档页 `pages/archive.vue`

**问题**
1. **日期列会溢出**：`substring(5)` 得到的是 `09-12 10:30:00`（14 字符），却塞在 `w-20`（80px）的 `flex-shrink-0` 容器里，`text-xs` 下装不下。`archive.vue:14`
2. **没有总数、没有年份快速跳转**，纯嵌套列表，文章一多就变成"无限长的墙"。`archive.vue:6-19`
3. **没有空状态**：一篇文章都没有时页面是一片空白。`archive.vue`（无 `length === 0` 分支）
4. `v-else` 与 `v-for` 写在同一元素上，属于 Vue 不推荐写法（虽然能跑）。`archive.vue:6`

**优化方向**：日期只保留 `MM-DD` 并加 `whitespace-nowrap`；顶部加"共 N 篇 · M 个年份"与年份锚点导航；时间轴样式的左侧竖线；补空状态；把 `v-else` 与 `v-for` 拆开。

**预期收益**：一眼看清全站体量；长归档可快速定位。

**优先级**：P1（日期溢出、空状态）；P2（时间轴、统计）

### 2.7 关于页 `pages/about.vue`

**问题**
1. 🔴 **重开了 XSS 口子**：`MarkdownIt({ html: true })` + `v-html`。而 `MarkdownRenderer.vue` 是**刻意关掉** `html` 并注释说明"避免配合 v-html 造成存储型 XSS"。关于页把这条防线撤掉了 —— 虽然目前只有管理员能写 `aboutContent`，但这是安全策略的自相矛盾。`about.vue:38` vs `MarkdownRenderer.vue:27-29`
2. **内容不走 SSR**：`fetchLinks()`/`fetchConfig()` 在顶层直接调用（客户端），于是首屏 HTML 里**关于页正文是空的**，爬虫抓不到；页面上还会先闪一下"暂无友链"。`about.vue:64-65`
3. **`siteName` 取的是 `res.data.siteName`，但后台设置里根本没有这个字段**，永远回退到硬编码值。`about.vue:52`
4. **博主信息完全没用设置**：`bloggerName`/`bloggerBio`/`bloggerAvatar` 三个设置项在关于页都没有被渲染，关于页本来最该展示它们。

**优化方向**：改回 `html: false`（若确需表格/换行等，用受控的自定义规则而不是放开全部 HTML）；两个请求改 `useAsyncData` 走 SSR；补博主卡片（头像/昵称/简介）并使用站点设置。

**预期收益**：安全策略一致；关于页可被收录且不闪；后台设置终于生效。

**优先级**：**P0**（第 1 条）；P1（2、4）

### 2.8 登录页 `pages/login.vue`

**优先级**：P1（1、2）；P2（3、4、5）

### 2.9 OAuth 回调页 `pages/oauth/callback.vue`

**问题**

**预期收益**：登录失败不再是"无声黑洞"；登录后可回到原处。

**优先级**：P1（1、2）；P2（4）／安全项单列

### 2.11 AI 助手 `components/AiFloat.vue`

**问题**
1. **中文输入法回车会误发送**：`@keydown.enter.exact.prevent` 没有判断 `isComposing`，用拼音选词时按回车会直接把半成品发出去。对中文用户影响很直接。`AiFloat.vue:92`

**预期收益**：中文输入不再误发（很关键）；长问题可读；可中止、可保留会话。

## 四、横切面问题（影响所有界面）

### 4.1 无障碍（Accessibility）

**问题**
- 全站**没有任何 `prefers-reduced-motion` 处理**：星空、粒子、鼠标拖尾、鼠标光斑、页面入场动画、Logo 翻转在"减少动态效果"的系统设置下依然全速运行（已验证）。
- 3 处 `<img>` 缺 `alt`（已验证）。
- 多个纯图标按钮只靠 `title` 或字符（`✕`/`☰`），没有 `aria-label`。
- 弹窗普遍缺 dialog 语义、焦点陷阱与初始焦点（Header 设置弹窗、mermaid 放大遮罩）；AppConfirm 的 Esc 实际失效。
- Toast 错误态用 `role="status"` 而非 `role="alert"`。

**优化方向**：`main.css` 加 `@media (prefers-reduced-motion: reduce)` 全局降级；补 `alt`/`aria-label`；抽一个统一的 `Modal` 组件解决焦点管理。

**预期收益**：键盘/读屏用户可用；晕动症用户不被动画困扰；也是 SEO 的间接加分项。

**优先级**：P1

### 4.2 移动端

**问题**
- 长文**无目录**（2.2-4）。
- 代码块**没有复制按钮**（2.4-2）。
- 上下文"AI 解释"**触屏无法触发**（2.2-7）。
- 登录页**没有返回首页入口**（2.8-1）。
- 后台 8 项导航靠隐藏滚动条横滑（3.1-2）。
- 分页组件在窄屏会折成 3–4 行（`Pagination.vue:2`，`flex-wrap` 且元素多达 7 类）。

**优化方向**：统一做一次窄屏走查；分页在窄屏降级为"上一页 / 3 / 12 / 下一页"。

**预期收益**：手机访客（通常是多数）体验接近桌面。

**优先级**：P1

### 4.3 交互细节

**问题**
- 全站**没有 URL 状态同步**：首页分页/分类、后台列表分页都不写 URL（2.1-1、3.2）。
- 全站**没有"锚点避让固定头部"**（2.2-3）。
- 日期到处用 `createTime.substring(...)` 硬切字符串，格式不统一（首页/归档/文章页/后台各不相同）。
- 骨架屏与真实内容的圆角、条数经常对不上（2.1-3、3.2-7）。

**优化方向**：抽 `useQueryState` 组合式函数统一同步 URL；全局 `scroll-margin-top`；抽 `formatDate()` 统一日期；统一骨架组件。

**预期收益**：可分享、可刷新、可后退；视觉不再跳。

**优先级**：P1

### 4.4 可维护性（会影响 UI 改动成本）

**问题**
- **域名硬编码 15 处**，散落在 6 个文件（`index.vue`/`article/[id].vue`/`post/[slug].vue`/`about.vue`/`archive.vue`/`nuxt.config.ts`）。换域名或加预览环境要大改。`grep -rn codeup.asia`
- **`useSiteConfig` 组合式函数已存在但没人用**，两个布局各自在 `onMounted` 里重复请求 `/site-config/public`（每次进布局一次请求，且走不了 SSR）。`composables/useSiteConfig.ts`
- `articles/index.vue` 导出时用 `$fetch` 手动拼 `Authorization` 头，绕过了统一的 `useApi`。
- **`post/[slug].vue` 与 `article/[id].vue` 大段逻辑重复**（SEO meta、JSON-LD、取数），是"改一处漏一处"的结构性根因。

**优化方向**：域名收进 `runtimeConfig.public.siteUrl`；布局改用 `useSiteConfig`；导出也走 `useApi`；把文章详情抽成一个组件/组合式函数供两条路由复用。

**预期收益**：后面每一项 UI 改动的成本都会下降；这也是 2.2 那个 P0 问题的根治手段。

**优先级**：P1

## 五、实现这些优化时的约束与影响

1. **改文章详情页结构（2.2）风险最高**：`/post/{slug}` 与 `/article/{id}` 的 canonical、JSON-LD、sitemap、以及已发布外链都依赖现有 URL。**合并 UI 时不要改动路由与 canonical 规则**，只统一"渲染层"。改完必须回归：直接访问两条 URL、站内跳转、搜索引擎抓到的 canonical 是否仍指向 slug 版。
2. **复制代码修复（2.4-1）要注意 HTML 体积**：若用"额外挂一份原始文本"的方案，长代码块会让 HTML 变大约一倍；用"行间补 `\n`"的方案更省，但要顺带处理末尾 `&nbsp;` 占位，别把 `&nbsp;` 也复制进去。改完请**实际粘贴到编辑器/终端验证**。
3. **删掉 profile 的密码字段（2.10）是前后端联动**：前端删字段，后端 `AuthController` 的密码分支也要一并处理，否则字段删了后端逻辑还在，属于"半下线"。另外要确认现网库里是否已有用户设过密码——若有，需决定是否清理。
4. **关于页 `html:false`（2.7）会缩窄可写范围**：如果现有 `aboutContent` 里已经用了裸 HTML（比如 `<div>`、`<br>`、`<style>`），改完会直接显示成源码。**动手前先看一眼现网关于页内容**，必要时保留少量白名单标签。
5. **站点设置 4 项生效（3.5）涉及"以谁为准"**：首页侧栏目前显示的是**登录用户**的头像/昵称，而 `bloggerAvatar` 是**博主本人**的。这两者语义不同，不能简单替换，需要先明确侧栏到底要展示谁。
6. **移除全局主题色/背景色覆盖（1.2-4）会改变现有观感**：现在的实现虽然危险，但确实生效了。改成 CSS 变量方案后，请在所有主要页面（含暗色模式、后台、编辑器、代码块）逐一比对，避免出现"某个角落没跟着变"。
7. **日志持久化 / 服务器配置类改动不在本清单范围**：本清单只涉及前端界面。若同时进行上次那份「服务器加固与备份执行手册」的操作，注意**不要在部署窗口内叠加 UI 改动**，否则出问题不好定位是哪一批改动引起的。
8. **无自动化回归**：前端没有 E2E 测试、没有视觉快照，`nuxi build` 在本机也跑不起来（沙箱限制）。因此上面每一项改动都**依赖人工走查**，建议一次只改一个界面并附上自测清单。
9. **性能预算**：全站已有星空/粒子/canvas/光斑等多层动画，再加动效会明显拖慢低端机。`prefers-reduced-motion` 与"暂停非可见动画"建议与其它改动一起做，而不是最后补。
