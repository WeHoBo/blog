> 全部建议按优先级排序。**本文只做建议，未改动任何代码。**

> **⏱️ 时效状态（2026-09-20 归档时整理）**
> - ✅ 已落地：第 5 节三个 P0 首选已于 2026-09-12 实施（图片灯箱、代码块升级、标签/分类独立落地页，见 `docs/archive/P0三项改动报告.md`）；其后又完成文章详情双路由合一、相关推荐、编辑器回收站/版本历史/素材库/定时发布。

## 0. 前提：我对你项目的理解

> 下面这些是从代码里读出来的，**如果与实际不符请直接指出**，我再据此修正建议。

| 项 | 现状 |
|---|---|
| 前端 | Nuxt 3（Vue 3 + TypeScript，SSR）+ Tailwind CSS 3 + Pinia |
| 后端 | Spring Boot 3 + MyBatis-Plus + MySQL + Redis + Spring Security(JWT) |
| AI | 独立 FastAPI + ChromaDB + DeepSeek（RAG，支持 PDF 与文章灌库） |
| 部署 | Nginx + systemd + 阿里云 OSS 图床 |
| 类型 | 单人技术博客（唯一作者是 admin，登录只有 OAuth） |
| 已有 | 文章/分类/标签/归档/友链/评论(平铺)/版本历史/回收站/操作日志/站点设置/AI 悬浮助手/主题色与暗色模式 |

**一句话定位**：这是个"自研程度很高、但 UI 打磨与内容运营能力偏弱"的技术博客——**RAG、版本历史、回收站这些"重功能"都有了，缺的反而是一些成熟博客系统的标配**。所以下面的建议偏"抄成熟项目的界面与交互"。

## 2. 详细建议

### P0 · 立刻可做

---

#### 1. 正文图片点击放大（灯箱）

- **参考**：`francoischalifour/medium-zoom`（极轻量，点击图片平滑放大，几乎零配置）；`dimsemenov/PhotoSwipe` v5（功能全：双指缩放、左右切换、键盘、手势）。界面示例：`saicaca/fuwari`、`jerryc127/hexo-theme-butterfly`、`vuepress-theme-hope` 的文章配图查看器。
- **拟引入**：给 `.article-content img` 统一挂灯箱——点击全屏、滚轮/双指缩放、`Esc` 关闭、多图 `←/→` 切换、`title` 作为图注、加载失败显示占位。
- **价值与适用场景**：技术文章里大量是**截图与架构图**，现在**完全点不开**（反而 mermaid 手写了放大遮罩，体验不对称）。对任何带图长文都直接生效，收益立竿见影。
- **优先级**：**P0**（改动最小、体感提升最直接）

---

#### 2. 代码块升级：文件名 + 行高亮 + 折叠

- **参考**：`expressive-code/expressive-code`（Astro 生态，代码块功能的标杆：标题、行高亮、折叠、终端样式、diff）；**VitePress 的 `{1,3-5}` 行高亮语法**；底层可用 `shikijs/shiki`（VS Code 同款语法着色）。
- **拟引入**：
  - 支持围栏语法带元信息：```` ```js title="server.js" {3-5} ```` → 渲染出**文件名标签 + 高亮第 3–5 行**；
  - 超过 ~30 行的代码块默认折叠，右上角「展开」；
  - 复制按钮（已修）旁增加「换行开关」（有些场景需要不带换行的单行复制）。
- **价值与适用场景**：教程类文章的可读性提升明显——读者一眼知道"这段属于哪个文件""重点是哪几行"。现状只有基础着色 + 复制。
- **优先级**：**P0**（改动集中在 `MarkdownRenderer`，但收益密度很高）

---

#### 3. 标签云 / 标签页 / 分类页独立落地页

- **参考**：`jerryc127/hexo-theme-butterfly` 的**标签页 + 标签云（字号随文章数变化）**、`next-theme/hexo-theme-next` 的 tags/categories 页、`saicaca/fuwari` 的 tags 页。
- **拟引入**：新增 `/tags`（标签云）、`/tag/{slug}`、`/categories`、`/category/{slug}`，**每个页面独立 title / description / canonical**，列表里带文章数与最近更新。
- **价值与适用场景**：现状标签/分类都跳回 `/?tagId=x`，**没有独立 URL**；而 canonical 又统一指向 `/post/{slug}`，等于告诉搜索引擎"这些聚合页别收录"。这是**纯 SEO 收益、成本极低**的一步，适用所有内容型站点。
- **优先级**：**P0**

---

#### 4. RSS / Atom + 页脚导航

- **参考**：VanBlog **内置 RSS 订阅**；`hexo-theme-butterfly` 的 RSS 图标；`saicaca/fuwari` 的 RSS；Nuxt 生态 `@nuxtjs/feed`。
- **拟引入**：`/rss.xml`（可直接照你现有 `SitemapController` 的写法再写一个 Controller）+ **页脚改两栏**：热门分类 / 快捷入口 / RSS / 社交入口 / 最近更新。
- **价值与适用场景**：技术读者仍然大量使用 RSS 阅读器，这是"一次开发、长期自动获客"的渠道。而你现在页脚只有版权 + 备案号，**这是内链与二次导流的黄金位置，完全浪费**。
- **优先级**：**P0**

---

#### 5. 媒体库（图片/附件管理）

- **参考**：**Halo 2.x 的「附件」管理**——Halo 官方把"改进附件管理方式"列为 2.0 的核心亮点之一；`Molunerfinn/PicGo` / `Kuingsmile/PicList` 的图床相册视图；WordPress 媒体库。
- **拟引入**：后台新增「媒体」页——**网格缩略图 + 按文件名搜索 + 一键复制 Markdown/URL + 删除 + 查看被哪些文章引用**（引用检查能防止"删了图导致文章裂图"）。
- **价值与适用场景**：你有 `/upload` 接口和 OSS，但**上传完就找不到了**，只能靠记 URL。文章一多，OSS 上的文件无法管理。对长期写作者是刚需。
- **优先级**：**P0**

---

#### 6. 文章系列导航（series）

- **参考**：`vuejs/vitepress` 的 **sidebar 分组**（左侧目录 + 底部「上一章/下一章」）；`facebook/docusaurus` 的 docs 侧栏；`xaoxuu/hexo-theme-stellar` 的系列文章。
- **拟引入**：文章页展示"**本系列共 N 篇**"的目录（高亮当前篇，可折叠），底部保留系列内上一篇/下一篇；`/series/{name}` 做系列落地页。
- **价值与适用场景**：`article.series` 字段与 `/api/article/series` 聚合接口**都已经存在**，但**前端一点没做**——现在只能后台手填系列名，读者完全看不到。对连载型教程，系列导航的留存价值通常**高于**单篇相关推荐。
- **优先级**：**P0**

---

### P1 · 值得排期

---

#### 7. 后台数据看板

- **参考**：**VanBlog 的「分析概览」**（内置流量统计 + 精美看板，是其主打特性之一）；**Halo 的仪表盘**；`umami-software/umami` 的开源分析看板（图表与信息层级可参考）。
- **拟引入**：一屏概览——文章/评论/阅读的趋势折线、热门文章 Top10、最近评论、**待处理项**（回收站里有几篇、几篇缺摘要/缺封面、几条未审核评论）。
- **价值与适用场景**：你现在 `/admin` 直接就是文章列表，**没有任何概览**。写作是长期行为，**没有反馈的写作很难坚持**——这个看板是"情绪与决策"双重支撑。
- **优先级**：**P1**

---

#### 8. 评论系统升级（楼中楼 / 通知 / 审核）

- **参考**（三个都成熟、都自托管）：
  - `twikoojs/twikoo`——自带**管理面板**、邮件/IM 通知、表情、Markdown、反垃圾（Akismet/腾讯云）、访问量统计；
  - `walinejs/waline`——功能最全，支持**文章表态（reaction）**、社交登录（QQ/微信/GitHub）、多来源数据迁移；
  - `ArtalkJS/Artalk`——有独特**侧边栏「我的评论」**、评论置顶与折叠、插件系统。
- **拟引入**（两条路，建议选其一）：
  - **路线 A（省力）**：自托管 Twikoo 或 Waline，博客侧只留一个挂载点，**把评论的楼中楼、表情、通知、审核全部交给它**；
  - **路线 B（保留自研）**：至少补齐 **楼中楼（`parentId` 字段已就绪）→ @提醒 → 表情 → Markdown → 站长回复邮件通知 → 先审后发**。
- **价值与适用场景**：你现在的评论只有平铺列表 + 一个 textarea，**无回复、无通知、无审核**，`parent_id` 与 `status` 两个字段白白闲置。评论是博客唯一的"活人感"，也是站长敢不敢开放评论的前提。
- **优先级**：**P1**（路线 A 性价比明显更高）

---

#### 9. 全文搜索

- **参考**：`Pagefind/pagefind`（Docusaurus / Starlight 的默认搜索，构建期生成索引、纯前端检索、零服务）；`meilisearch/meilisearch`（VitePress/Next 生态常用，独立服务、中文友好、带高亮与容错）；`saicaca/fuwari` 就用 Pagefind。
- **拟引入**：
  - **A 起步**：MySQL `FULLTEXT` + `WITH PARSER ngram`，把搜索从 `title` 扩到 `summary/content`，结果页**高亮关键词 + 显示上下文片段**；
  - **B 进阶**：复用你**已有的 ChromaDB** 做语义搜索（问"缓存击穿怎么解决"能命中讲缓存的文章）。
- **价值与适用场景**：现在搜索**只 `LIKE` 标题**，而搜索框 placeholder 却写着「搜索文章、标签、分类」——这是对用户的**虚假承诺**。搜索是内容站的第二大入口。
- **优先级**：**P1**

---

#### 10. 编辑器升级为工具栏式 Markdown 编辑器

- **参考**：`Vanessa219/vditor`（链滴/B站同款，三种模式 + IR 即时渲染 + 工具栏 + 上传）；`imzbf/md-editor-v3`（Vue 3、中文作者、工具栏+预览+目录+图片上传+主题）；`bytemd/bytemd`（掘金同款，插件化）。
- **拟引入**：工具栏（加粗/标题/列表/引用/表格/链接/行内代码/代码块/图片）、**粘贴或拖拽图片直传 OSS**、全屏写作、大纲、快捷键、字数统计。
- **价值与适用场景**：你现在是 CodeMirror + 分栏预览，**没有工具栏**；插图还得"先上传、再复制链接、再粘回来"三步。这是站长每天都要用的界面，**边际收益最高**。
- **优先级**：**P1**（改动面较大，建议单独一轮）

---

#### 11. RAG 知识库问答正式入口

- **参考**：Halo 把**评论与搜索做成插件**、由主题按需挂载的思路；`facebook/docusaurus` 生态的 "Ask AI" 问答（带**引用来源卡片**）；通用 Chatbot UI 项目的"来源引用 + 可点跳转"交互。
- **拟引入**：正式入口页（现 `/ai` 已废弃为跳转）+ **把 RAG 返回的 `sources` 渲染成可点击卡片，直接跳到对应文章** + **会话历史持久化**（你 RAG 侧已有 `/history` 接口，前端却在用内存态，刷新即丢）。
- **价值与适用场景**：你**已经建好**了 FastAPI + ChromaDB + DeepSeek 的一整套 RAG（还支持 PDF 灌库），但博客侧**没有任何入口**——能力 100% 闲置。它既能服务访客，也是你技术能力最直观的展示面。
- **优先级**：**P1**

---

#### 12. SEO 元数据专业化 + 去硬编码域名

- **参考**：`nuxt-modules/seo`（`@nuxtjs/seo`：sitemap / robots / schema-org / og-image 一体）；`nuxt-modules/og-image`（自动生成分享图）；`timlrx/tailwind-nextjs-starter-blog`（内容站 SEO 配置的样板）。
- **拟引入**：① 把**硬编码的域名收敛到 `runtimeConfig.public.siteUrl`**（现在散在 6 个文件、约 15 处）；② 面包屑结构化数据（`BreadcrumbList`）；③ **动态 OG 图**（现在 `ogImage` 固定是 `apple-touch-icon.png`）；④ robots 规则。
- **价值与适用场景**：域名单点配置后，换域名/加预览环境不用全局搜替换；结构化数据能让搜索结果带面包屑，提升点击率。
- **优先级**：**P1**

---

#### 13. 图片优化（WebP / srcset / 防跳动）

- **参考**：`nuxt/image`（Nuxt 官方模块，支持 IPX/OSS 等 provider）；Next.js 的 `<Image>` 作为设计参照。
- **拟引入**：正文与卡片图片统一改 `<NuxtImg>` / `<NuxtPicture>` → **自动格式协商（WebP/AVIF）、按屏宽出 srcset、带宽高比占位（消除 CLS）、懒加载**；封面补 `alt` 与 `onerror` 兜底。
- **价值与适用场景**：现在 `<img>` **没有尺寸、没有 srcset**，导致封面加载时**列表整体跳动**，长文首屏一次性请求所有图。对流量和体感都有影响。
- **优先级**：**P1**

---

#### 14. 无障碍 + 动效标准化

- **参考**：`vueuse/vueuse`（`usePreferredReducedMotion`、`useFocusTrap`、`useClipboard`、`useEventListener`、`useStorage` 等组合式函数）；`unovue/reka-ui`（前 Radix Vue，**Nuxt UI 无障碍原语底座**：对话框焦点陷阱、Esc、`aria-modal` 开箱即用）。
- **拟引入**：用 VueUse 替换手写的事件监听/剪贴板/本地存储；用 Reka UI 的 Dialog/Popover 替换手写弹窗（解决"点外不关、Esc 失效、无焦点管理"）；全站统一 `prefers-reduced-motion` 降级开关（星空、粒子、拖尾、光斑、入场动画一起受控）。
- **价值与适用场景**：现有审计已确认：**全站没有 reduced-motion 处理**、弹窗普遍缺 dialog 语义与焦点陷阱、Toast 错误态用了 `role="status"`，且手写的 canvas 拖尾**有内存泄漏**（匿名监听无法移除）。用成熟库替换手写实现，**同时解决可访问性、性能与维护成本**。
- **优先级**：**P1**

---

#### 15. 移动端目录 + 目录高亮修正

- **参考**：`vuepress-theme-hope` 的 TOC（层级化 + 滚动高亮 + 进度）；`saicaca/fuwari` 的 `TableOfContents`；`hexo-theme-butterfly` 的目录与阅读进度。
- **拟引入**：
  - **同名标题 ID 去重**（`标题`、`标题-1`…），且**渲染端与目录端共用同一个函数**（抽成 `useHeadingAnchor`）——现在两处各写一遍，同名标题会撞 ID、点第二个跳到第一个；
  - **只保留一套高亮策略**（现在 IntersectionObserver 与 scroll 监听同时写 `activeId`，快速滚动会抖）；
  - **移动端抽屉目录**（现在 `hidden lg:block`，手机上长文**完全没有目录**）。
- **价值与适用场景**：长文在手机上的可导航性，以及"点目录没反应"这类直接挫伤信任的 bug。
- **优先级**：**P1**

---

#### 16. 友链自助申请

- **参考**：`jerryc127/hexo-theme-butterfly` 的友链页；Halo 主题生态里的"友链申请"表单；VanBlog 的友链管理。
- **拟引入**：前台表单（站点名/URL/头像/简介/一句介绍）→ 后台"待审核"列表 → 一键通过后自动出现在关于页；附"申请须知"（如要求先加本站）。
- **价值与适用场景**：换友链现在是私聊过程。友链是个人博客**最廉价的外链来源**，把流程产品化能显著提高成功率。你后台的 `FriendLink` CRUD 已经有了，只缺前台入口与待审状态。
- **优先级**：**P1**

### P2 · 锦上添花

#### 17. 写作热力图
- **参考**：**GitHub 个人主页的贡献图**（事实标准）；`wa0x6e/cal-heatmap`（可定制热力图库）。
- **拟引入**：关于页/个人中心展示"过去一年写下的格子"，悬停显示当天篇数与标题。
- **价值与场景**：按 `create_time` 聚合即可（`/archive` 已在做类似聚合）。**情绪价值大于功能价值**，但对"坚持写作"很有效。

#### 18. 稍后读 / 阅读进度续读
- **参考**：VanBlog 的草稿与加密、掘金收藏夹的交互；`vueuse` 的 `useStorage` 可做本地版。
- **拟引入**：文章页"收藏/待读"按钮 + 列表页"我的待读"入口 + 回到文章时从上次位置继续。
- **价值与场景**：通勤碎片阅读（**移动端为主**）的场景补齐。先做纯前端本地版（零后端），再考虑跨设备。

#### 19. 动态分享卡片（OG 图）
- **参考**：`nuxt-modules/og-image`；Vercel 的 OG Image Generation（基于 Satori 的 JSX→SVG→PNG）。
- **拟引入**：分享到微信/即刻时自动生成"标题 + 作者 + 站点 + 二维码"的分享图；文章页提供"生成卡片"下载按钮。
- **价值与场景**：传播效率直接决定"出圈"概率。现在 `ogImage` 是固定图标，社交平台抓不到有效信息。

#### 20. 版本历史可视化 diff
- **参考**：**GitHub 的 diff 视图**（左右/统一视图、行级高亮、展开上下文）；`kpdecker/jsdiff` 等 diff 库。
- **拟引入**：版本列表里选两版对比，行级高亮新增/删除，支持"以当前版本为基准"。
- **价值与场景**：`ArticleRevision` 与版本列表页**已有**，但只能看整篇内容、**没有对比**，回滚前得肉眼比对。回滚是低频高风险操作，diff 能实质降低"越改越乱"。

#### 21. 草稿分享预览链接
- **参考**：**Halo 的"预览"**、Notion 的 share link、WordPress 的"预览发布"。
- **拟引入**：为草稿生成带随机 token 的临时链接（可设 7 天过期、可撤销），朋友无需登录即可查看。
- **价值与场景**：给朋友校对、投稿预览。现在草稿只能自己登录后台看。

#### 22. 文章底部"发现错误？"入口
- **参考**：**Docusaurus 的 `editUrl`（"Edit this page"）**、VitePress 的 `editLink`。
- **拟引入**：文章底部一行"发现错误或有建议？告诉作者"→ 弹窗预填当前文章标题与链接，走邮件/表单/GitHub Issue。
- **价值与场景**：读者是最便宜的校对资源。现在读者发现错字**无处反馈**，只能默默离开。

#### 23. PWA / 离线阅读
- **参考**：`vite-pwa/nuxt`（`@vite-pwa/nuxt`）；`vite-plugin-pwa`。
- **拟引入**：可"添加到桌面"、离线可读已访问文章、弱网快速打开。
- **价值与场景**：移动端回头读者体验提升。**注意**：Service Worker 缓存 HTML 很容易造成"部署了新版本用户还是看到旧的"，必须做版本化与失效策略——这也是我把它排在 P2 的原因。

## 4. 落地约束（这些会影响选型）

1. **Nuxt 3 SSR 是双刃剑**：`Pagefind` 这类"构建期生成索引"的方案天然适合你（静态索引 + SSR 页面）；但 `@vite-pwa/nuxt` 的 Service Worker **必须做版本化缓存**，否则会出现"部署了新版而用户看到旧版"。
2. **评论系统换 Twikoo/Waline 会引入第 4 个进程**：你已经有 Java 后端、独立的 Python RAG 进程，再加一个 Node 服务会提高运维复杂度。**权衡点**：省下的自研成本 vs 多一个服务要养。若不想加进程，就走"自研补齐楼中楼"的路线。
3. **`ngram` 分词必须在建索引时指定**（`WITH PARSER ngram`），否则中文全文搜索形同虚设——这是 MySQL 上最常见的坑。
4. **媒体库若做"引用检查"要注意性能**：正文是 LONGTEXT，全表 `LIKE` 查引用会慢；建议用"文章列表只取 `id+content_md` 前缀"或维护一张引用关系表。
5. **编辑器替换（Vditor / md-editor-v3）风险最高**：你现在有**自动保存 + 版本快照**逻辑挂编辑器上，换编辑器必须把这两块重新对齐，否则会丢草稿。**建议单独一轮做，并先写自测清单**。
6. **RAG 相关功能依赖进程同机**：RAG 绑 `127.0.0.1`，且要两侧都配 `RAG_API_TOKEN` 才生效。做"知识库入口页"前先确认这条链路是通的。
7. **不要一次做太多**：本机无法完整构建（沙箱限制 `nuxi build`）、没有 E2E 与视觉快照，**所有改动都靠人工走查**。建议**一批只动 2–3 项**，每项配自测清单。
8. **Halo/VanBlog 只需"抄功能与交互"，别抄架构**：Halo 是"微内核 + 插件 + 多用户 RBAC"，VanBlog 是"React + MongoDB + 静态化"。你的项目是"单人 + Nuxt SSR + MySQL"，**直接照搬架构只会得不偿失**。

## 5. 如果只挑三件

1. **正文图片灯箱（#1）** —— 半天级改动，**所有带图文章的体感立刻提升**，是目前最高性价比的一件事。
2. **代码块增强（#2）** —— 你是技术博客，"看代码"就是核心场景，文件名 + 行高亮的密度比任何装饰都高。
3. **标签/分类独立落地页（#3）** —— 修掉现有的 SEO 缺陷（聚合页无独立 URL 且不被收录），成本极低、长期复利。
